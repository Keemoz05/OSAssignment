Use of make 

All log messages must be:
– Complete (no interleaving)
– Ordered (chronologically consistent)
– Non-blocking to gameplay

Persistent Storage: The server must maintain player win statistics in a file named
scores.txt.

Loading: The server must load the scores.txt file into shared memory upon
server startup. If the file does not exist, it should be created.

• Updating: At the conclusion of every game, the winning player’s score must be
atomically updated in the shared memory structure.
• Saving: The server must write the updated scores from memory back to scores.txt
upon server shutdown (using signal handling, e.g., SIGINT) and potentially after every completed game
